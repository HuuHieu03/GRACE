## 2. Nhật Ký Khắc Phục Lỗi Ngữ Cảnh (Context Window Remediation)

### Vấn đề gặp phải ở Version 9:
- Cấu hình server cũ: `--n_ctx 4096`.
- Ở Arm B2 (GRACE: Code + CPG + Demonstration), nhiều hàm C/C++ có đồ thị phụ thuộc dữ liệu/điều khiển lớn kèm ví dụ minh họa dẫn đến độ dài prompt vượt quá 4,096 tokens.
- Hậu quả: `llama-server` trả về mã lỗi `HTTP 400 Bad Request` cho 120 mẫu phức tạp nhất, khiến `invalid_rate` bị đẩy lên 2.2% và thiếu sót dữ liệu.

### Giải pháp kỹ thuật áp dụng ở Version 10:
1. **Mở rộng ngữ cảnh tối đa của server**:
   ```bash
   ./llama-server \
       --model ./models/qwen2.5-coder-7b-instruct-q4_k_m.gguf \
       --n_ctx 8192 \
       --n_gpu_layers 99 \
       --threads 4 \
       --host 127.0.0.1 \
       --port 8080 \
       --cont-batching \
       --flash-attn
   ```
2. **Đồng bộ hóa với `TokenBudgetManager`**:
   - Target code budget: tối đa 3,000 tokens.
   - Graph representation budget: tối đa 1,500 tokens.
   - Demonstration budget: tối đa 1,500 tokens.
   - Output reserve: 64 tokens.
   - Tổng context an toàn: $\le 8,192$ tokens.
3. **Tối ưu hóa pipeline**:
   - Sử dụng kết nối HTTP Keep-Alive cục bộ.
   - Rút gọn quá trình trích xuất `top_logprobs=5` không cần qua trung gian tunnel.
   - Giảm thời gian trễ giữa các request.
