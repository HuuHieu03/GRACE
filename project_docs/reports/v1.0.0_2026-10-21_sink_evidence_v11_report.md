# Triển khai E1.1: mở rộng registry wrapper

Đã thêm `src/security_signature/sink_evidence_v11.py`. E1.1 dùng nguyên scanner E1 rồi phân loại lại các direct call-site Unknown có tên khớp chính xác với 25 rule mới. Không sửa source/registry E1 đã đóng băng, production extractor, similarity, reranker, guard hoặc prompt.

## 1. Rule và nguồn bằng chứng

25 rule được ghi tường minh trong mapping bất biến `NEW_WRAPPER_RULES`; không tự nạp từ JSON kết quả hay tự học family từ target label. Các nhóm gồm cấp phát/giải phóng, buffer read/write, mở/đóng file và thay đổi metadata filesystem. Mỗi evidence mới có `rule_id`, family, span gốc và `semantic_validation` phản ánh việc mới được rà theo caller context, chưa có audit độc lập body/contract wrapper.

Các API như ff_thread_get_buffer được gán family alloc theo nhóm hành vi cấp/acquire buffer trong annotation; không có nghĩa mọi lần gọi luôn cấp phát mới. Gán family thao tác không chứng minh có taint path, guard hiệu quả, free đã xảy ra thành công hay có vulnerability.

Chỉ promote lời gọi `direct_call_site` với lý do `unresolved_helper_or_function`. Member/qualified calls, prefix/suffix gần giống, prototype, comment và string không được promote. Macro/helper chưa có rule giữ Unknown. Evidence cũ E1 được giữ nguyên, thứ tự call-site theo offset được bảo toàn.

## 2. Kết quả hồi quy trên 50 mẫu phát triển

Đây là 50 mẫu đã dùng để thiết kế 25 rule, nên số liệu đo **khả năng sửa các ca đã biết**, không phải held-out accuracy.

| Exact call-site | E1 | E1.1 |
| --- | ---: | ---: |
| TP | 33 | 67 |
| FP | 0 | 0 |
| FN | 34 | 0 |
| Precision | 100% | 100% |
| Recall | 49.25% | 100% |

Cả 34 Unknown đã annotate được phân loại, đúng API/span/family trong phạm vi đáp án. Các thao tác ngoài phạm vi như asm/array access và helper chưa resolve vẫn không được bao phủ bởi con số 67/67. Annotation kỹ thuật không trở thành ground truth độc lập chỉ vì E1.1 khớp hoàn toàn.

## 3. Kiểm thử

**332 tests pass** cho E1.1, E1 và bộ định vị annotation. Test E1.1 gồm các lời gọi của 25 rule cùng negative cases theo từng tên: comment, string, biến, prototype global/local, function definition, macro definition, member/namespace call và tên có suffix gần giống. Kiểm tra thêm E1 không bị mutate, Unknown khác vẫn còn và call thiếu ngoặc được giữ ở diagnostic.

Lệnh:

```powershell
python -m pytest tests/test_sink_evidence_v11.py tests/test_sink_evidence.py tests/test_sink_annotation_evaluation.py -q
python scripts/run_sink_evidence_v11.py
```

Sử dụng từ code có sẵn src trên Python path:

```python
from security_signature.sink_evidence_v11 import extract_sink_evidence

evidence = extract_sink_evidence(code)
```

## 4. Tập xác minh mới đã cố định

Đã tạo 50 mẫu dev mới từ `data/raw_c_files/devign/validation`, seed 20261021. Loại toàn bộ ID canonical dev-100, loại code trùng khi chuẩn hóa khoảng trắng với 100 mẫu cũ và giữa các mẫu mới. Chọn mẫu không dùng nhãn vulnerability hoặc prediction.

Manifest riêng có ID nguồn, hash code, source E1.1 và registry hash. Packet annotation chỉ có opaque ID E11-001..050, code và chỗ ghi đáp án; không đưa prediction, nhãn hoặc filename gốc vào packet. Chưa chạy prediction trên tập mới trong lượt này.
