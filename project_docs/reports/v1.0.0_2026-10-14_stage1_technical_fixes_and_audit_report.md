## 1. Tổng Quan Mục Tiêu

Báo cáo này tài liệu hóa chi tiết việc xử lý 3 chốt chặn kỹ thuật cốt lõi và bổ sung hệ thống đo kiểm (*Telemetry*) theo đúng chỉ đạo học thuật của Giảng viên Hướng dẫn:
1. **Loại bỏ hiện tượng Fail-to-Mock âm thầm**: Chương trình phải dừng và ném ngoại lệ rõ ràng khi thiếu API key, chỉ cho phép mock khi người dùng chủ động truyền flag `--use_mock`.
2. **Khóa toàn vẹn cấu hình vào Checkpoint (Config Integrity Hash)**: Ngăn chặn triệt để rủi ro khôi phục nhầm checkpoint của các thử nghiệm khác hoặc khi các tham số `(dataset, split, model, prompt_mode, retrieval_method, seed)` bị thay đổi.
3. **Sửa quy ước toán học Jaccard cho 2 tập rỗng trong Security Signature**: Khi cả 2 hàm đều không có Sink hoặc không có Sanitizer, trả về `0.0` thay vì `1.0`, triệt tiêu hiện tượng lạm phát điểm tương đồng an ninh (*SecSim Inflation*).
4. **Bổ sung Telemetry ghi nhận tần suất phân nhánh Fallback trong Contrastive Selector**: Theo dõi định lượng số lần và tỷ lệ top-50 ứng viên bị thiếu nhãn, dẫn tới việc phải kích hoạt lấy mẫu fallback từ tập train.

Điều này dẫn đến nguy cơ rất lớn là một thí nghiệm tưởng chừng chạy trên mô hình LLM thật lại đang âm thầm dùng hàm mock heuristic, làm sai lệch toàn bộ kết quả nghiên cứu khoa học mà không bị phát hiện.
* **Giải pháp triển khai**:
  ```python
  if not use_mock:
      api_key = config.get_api_key("FPT_API_KEY")
      base_url = config.get_base_url("FPT_BASE_URL")
      if not api_key:
          raise RuntimeError(
              "Lỗi cấu hình: Không tìm thấy FPT_API_KEY hoặc khóa API bị trống. "
              "Vui lòng cấu hình file .env hoặc biến môi trường trước khi chạy thực nghiệm. "
              "Nếu chỉ muốn kiểm thử giả lập nhanh mà không gọi API, hãy truyền flag --use_mock."
          )
      else:
          import openai
          logger.info(f"Kết nối tới API: {base_url} với model {self.model_name}...")
          self.client = openai.OpenAI(api_key=api_key, base_url=base_url)
  ```
* **Kết quả**: Ngăn chặn 100% việc chạy lén mock. Mọi lệnh chạy thực tế nếu cấu hình API lỗi sẽ dừng ngay tức thì và chỉ ra nguyên nhân cụ thể.

### 2.2. Bổ sung Config Integrity Hash cho `CheckpointManager`

* **File sửa đổi**: [`src/evaluator.py`](../../src/evaluator.py) và [`src/run_pipeline.py`](../../src/run_pipeline.py)
* **Vấn đề trước đây**:
  `CheckpointManager` chỉ dựa vào `experiment_name` để đặt tên file `checkpoint_{experiment_name}.jsonl`. Khi người dùng đổi `dataset`, đổi `model_name`, đổi `prompt_mode`, hoặc đổi `seed` mà vẫn giữ nguyên tên `experiment_name`, evaluator nạp lại các ID đã chạy từ file cũ, dẫn tới tình trạng kết quả kiểm thử là sự pha trộn hỗn tạp giữa nhiều cấu hình khác nhau.
* **Giải pháp triển khai**:
  1. `CheckpointManager` nhận thêm tham số `run_config: Optional[Dict[str, Any]] = None`.
  2. Tạo mã băm chuẩn hóa SHA-256 (12 ký tự hex đầu) từ dictionary cấu hình:
     ```python
     canonical_cfg = json.dumps(self.run_config, sort_keys=True, ensure_ascii=False)
     self.config_hash = hashlib.sha256(canonical_cfg.encode("utf-8")).hexdigest()[:12]
     filename = f"checkpoint_{experiment_name}_{self.config_hash}.jsonl"
     ```
  3. Khi tạo file checkpoint mới, dòng header đầu tiên ghi lại metadata cấu hình:
     ```json
     {"_type": "checkpoint_metadata", "experiment_name": "...", "config_hash": "...", "run_config": {...}, "created_at": "..."}
     ```
  4. Khi nạp lại checkpoint cũ, đối soát hash đã lưu với hash của phiên chạy hiện tại. Nếu có bất kỳ sự sai lệch nào (`saved_hash != self.config_hash`), hệ thống chủ động ném `RuntimeError` từ chối khôi phục để bảo vệ tính toàn vẹn của tập dữ liệu thực nghiệm.
  5. Trong [`src/run_pipeline.py`](../../src/run_pipeline.py), cấu hình `run_config` được đóng gói tự động gồm `{"dataset", "split", "model", "prompt_mode", "retrieval_method", "seed"}` và truyền vào `evaluator.evaluate_dataset`.

### 2.3. Quy ước Jaccard 2 tập rỗng trong `SecuritySignature`

* **File sửa đổi**: [`src/security_signature/similarity.py`](../../src/security_signature/similarity.py)
* **Vấn đề trước đây**:
  Trong `compute_jaccard_set(set1, set2)`:
  ```python
  if not set1 and not set2:
      return 1.0  # BUG: Cả 2 hàm không có sink -> tính là tương đồng an ninh tuyệt đối!
  ```
  Trong thực tế, khi 2 hàm C ngẫu nhiên đều không gọi hàm nguy hiểm (`sinks = []`) hoặc đều không có bộ lọc (`sanitizers = []`), chúng chỉ đơn giản là các hàm vô hại hoặc chưa phát hiện được sink, chứ không hề có chung một cơ chế bảo mật cụ thể nào. Việc gán `1.0` đã gây ra hiện tượng *SecSim Inflation* (điểm SecSim trung bình của các cặp ngẫu nhiên bị đội lên tới 0.76–0.96).
* **Giải pháp triển khai**:
  Sửa logic quy ước: Hai tập hợp chỉ được tính có độ tương đồng dương khi có ít nhất một phần tử an ninh xuất hiện đồng thời ở cả hai hàm. Nếu cả hai cùng rỗng, trả về `0.0`:
  ```python
  def compute_jaccard_set(set1: set, set2: set) -> float:
      """
      Tính chỉ số Jaccard giữa hai tập hợp.
      Nếu cả hai tập hợp đều rỗng, trả về 0.0 thay vì 1.0 vì không có bằng chứng an ninh chung
      (tránh hiện tượng thổi phồng tương đồng SecSim giả mạo).
      """
      if not set1 or not set2:
          return 0.0
      union_len = len(set1.union(set2))
      if union_len == 0:
          return 0.0
      return len(set1.intersection(set2)) / float(union_len)
  ```
* **Kết quả**: Triệt tiêu hoàn toàn điểm thưởng giả tạo giữa các hàm không có sink/sanitizer. Độ tương đồng an ninh phản ánh chính xác sự xuất hiện của các bằng chứng mã nguồn cụ thể.

### 2.4. Telemetry ghi vết phân nhánh Fallback trong `ContrastiveDemonstrationSelector`

* **File sửa đổi**: [`src/contrastive_selector.py`](../../src/contrastive_selector.py)
* **Vấn đề trước đây**:
  Khi lấy Top-50 ứng viên tương đồng nhất của một mẫu `query_sample`, nếu trong 50 ứng viên này chỉ toàn mẫu an toàn (`safe`) hoặc chỉ toàn mẫu có lỗi (`vuln`), thuật toán chọn cặp tương phản bắt buộc phải rẽ nhánh fallback sang lấy 5 mẫu đầu tiên của tập train có nhãn đối ứng và gán điểm giả lập `0.5`. Tuy nhiên, mã nguồn trước đây thực hiện rẽ nhánh trong im lặng, không ghi lại log hoặc số liệu thống kê để biết hiện tượng này xảy ra với tỷ lệ bao nhiêu %.
* **Giải pháp triển khai**:
  1. Thêm bộ đếm telemetry `fallback_stats` vào `ContrastiveDemonstrationSelector`:
     ```python
     self.fallback_stats = {
         "total_queries": 0,
         "fallback_count": 0,
         "missing_vuln": 0,
         "missing_safe": 0,
         "fallback_details": []
     }
     ```
  2. Bổ sung cảnh báo chi tiết qua `logger.warning` khi fallback kích hoạt, lưu lại `query_id`, nhãn bị thiếu, và danh sách các ID được chọn làm fallback.
  3. Cung cấp 2 phương thức:
     - `get_fallback_report()`: Trả về báo cáo thống kê định lượng gồm `total_queries`, `fallback_count`, `fallback_rate_pct`, `missing_vuln_count`, `missing_safe_count`, và mẫu log chi tiết.
     - `reset_fallback_stats()`: Đặt lại bộ đếm khi bắt đầu một phân vùng khảo sát mới.
